## 0. 目的

Phase 1-C-2 で「設計した Creator UI が動く」ことは確かめた。Phase 1-C-3 で確かめるのは、**このUIを人が触ったとき、自然に使えるか**である。

**テストを通すことより、迷った箇所を記録することが重要である。** 「PNG を出力できたから合格」ではなく、次のような観察を残す。

> EXPORT を探すのに 3 秒止まった
> 色の見本を押そうとした
> 「このパーツだけ色を変える」の意味を、最初は逆に理解した
> 注意が出た瞬間、キャラクターが縮んで違和感があった

新しい機能は作らない。レイアウト（案 B）も変えない。対象は、通知・詳細設定・カードなど、**各領域の内側の磨き込み**である。

## 1. 進め方

```text
準備（Claude Code）→ 操作検証（人）→ 修正方針の決定（人）→ 修正（Claude Code）→ 最終確認（人と Claude Code）
```

- ブランチは `phase1c-creator-ui` をそのまま使う。**Phase 1-C-3 が終わるまで main へマージしない。**
- 操作検証は人が行う。Claude Code は、検証できる状態を用意し、結果を受けて直す。
- 修正は、操作検証の結果と修正方針の決定を受けてから行う。観察の前に、推測で直さない（§3 の事前修正を除く）。

## 2. 変えないもの

- Asset Specification v1（RC1）と Character Schema v1（RC1）。`src/core/` の意味論。
- Character が唯一の正本であること。UI が持つ状態は、Phase 1-C-2 のレポート §6 の範囲（CREATE の入力中の値と「詳細設定を常に開く」を含む）。
- レイアウト案 B の 4 列と、下の段の帯。
- **素体の入れ替え、同じパーツの複製は扱わない**（意味論が未定のため、保留のまま）。
- UI フレームワークは導入しない。依存パッケージは増やさない。

## 3. 準備（Claude Code）

### 3.1 事前修正

操作検証の前に直しておくもの。判定で方向が決まっているものに限る。

| # | 内容 | 状態 |
| --- | --- | --- |
| A | **絵のないカードは名前だけにする**（表情・向き）。サムネイルがあるものは画像と名前。「なし」のカードは、絵の位置に「なし」とだけ出す | **実施済み** |
| B | **「外したパーツの設定」を、詳細設定から「設定」へ移す**。選択中のパーツの設定ではなく、キャラクター全体のデータの管理だからである | 【確認 1】 |
| C | **最近使った色を、押して選べるようにする** | 【確認 1】 |

### 3.2 通知の置き場所の比較

**中央のプレビューの大きさは、通知によって変化させない。** これを満たす置き場所を、実際の画面で比べられるようにする。

| 案 | 置き場所 | 特徴 |
| --- | --- | --- |
| 現状 | プレビューの下 | 通知の分だけプレビューが縮む（比較の基準として残す） |
| 1 | 右ペインの上 | 常に見える。右ペインの編集の内容が下に押される |
| 2 | プレビューに重ねる（下端） | 絵のすぐ近くに出る。絵の足元に重なる |
| 3 | 名前の横の「注意 n 件」を押すと開く | 普段は何も占有しない。開くまで内容が見えない |

- 比べるための切り替えは、URL の指定（例：`?notices=side`）で行う。画面には切り替えを出さない【確認 2】。
- 切り替えは検証のための一時的なもので、置き場所が決まったら、採用した案だけを残して消す。
- どの案でも、通知の内容と「外す」「向きを正面に戻す」などの操作は同じにする。

## 4. 操作検証（人）

### 4.1 環境

```sh
npm install
npm run dev     # http://127.0.0.1:5173/ を開く
```

- ブラウザの表示領域を **1280×800 程度**にして始める。課題 8 では幅を変える。
- 検証用の素材は仮素材（単純な図形）である。絵の出来は評価の対象にしない。

### 4.2 進め方

- **声に出しながら操作する**（または、操作の直後に書き留める）。止まった場所、探した場所、押そうとして押せなかったもの、予想と違った動きを記録する。
- 課題は、**画面の説明を読まずに**始める。分からなくなったら、分からなくなった場所を記録してから先へ進む。
- 「できたか」に加えて、「**迷わずにできたか**」を記録する。
- 課題 1 は最初に行う。**初見での印象は 1 回しか取れない**【確認 3】。

### 4.3 課題

優先度の高い順。

| # | 確かめること | 課題 | 特に見ること |
| --- | --- | --- | --- |
| 1 | 初見で一通りできるか | 何も読まずに、「新しいキャラクターを作り、髪型を変え、髪の色を変え、保存し、画像を書き出す」 | 最初にどこを見たか。どこで止まったか。保存と画像の書き出しを取り違えなかったか |
| 2 | プレビューの大きさが安定しているか | コートを着せて、右腕を「ポケット」にする。注意を外す。通知の置き場所の各案（§3.2）で繰り返す | 注意が出た・消えた瞬間に、絵の大きさや位置が変わるか。どの案が邪魔にならないか |
| 3 | いま編集しているパーツが分かるか | 服の色を変えた後、髪の分類を開き、もう一度服の色を変える | 右ペインが何を指しているか、迷わなかったか。別の分類を開いたとき、編集対象がどうなると思ったか |
| 4 | 全体の色と、パーツだけの色 | 髪全体を黒にする。その後、前髪だけを金色にする。前髪を全体の色に戻す | 「（全体）」と「このパーツだけ色を変える」の意味を、正しく予想できたか。逆に理解しなかったか。素体の「全体の色」に気づいたか |
| 5 | ポーズ・向き | 右腕のポーズを変える。キャラクターの向きを変えようとする | 向きが「ポーズ・向き」にあることに気づいたか。「素材なし」の意味が分かったか。邪魔に感じたか |
| 6 | 詳細設定 | メガネを少し上にずらし、少し傾ける。その後、「右腕がポケットのときだけ」位置を変える | 「詳細設定」に気づいたか。「いつ使うか」「中心」の意味が分かったか。数値だけで位置を合わせられたか。「元に戻す」が何を戻すと思ったか |
| 7 | 使えないパーツの理由 | 右腕が「ポケット」のままコートを着せようとする。トップスを「なし」にしてコートを着せようとする | 理由の文（「いまの向き・ポーズには未対応」「『トップス』が必要」）から、何をすればよいか分かったか |
| 8 | 画面の幅 | ブラウザの幅を 1024、1280、1600、1920 程度に変える | 崩れる幅。窮屈に感じる幅。広い画面で間延びするか |
| 9 | 導線と密度 | 全体を通して | EXPORT にすぐ気づいたか。カードの大きさ、プレビューの大きさ、右ペインの詰まり具合 |

課題の合間に、次も試す。

- 保存したファイルを読み込む。保存せずに「新規作成」を押す（確認が出る）。
- 読み込めないファイル（適当なテキストファイル）を読み込む。

### 4.4 検証後に決めること

観察をもとに、次を決める（修正方針）。

- 通知の置き場所（§3.2 のどれか、または別の案）。
- §3.1 の B・C を採るか（事前修正にしなかった場合）。
- Phase 1-C-2 のレポート §7 の残りの項目（一覧の余白、編集中のパーツの強調、パーツの名前の折り返し、CREATE でのプレビュー、「元に戻す」の言葉、「カスタム」の見せ方）のうち、直すもの。
- 観察で新しく見つかった問題のうち、直すものと、Phase 2 以降へ送るもの。

## 5. 記録の形

`docs/reports/Phase1C3_Observation_Sheet.md` に、課題ごとに次を書く。箇条書きでよい。

| 欄 | 書くこと |
| --- | --- |
| できたか | できた ／ 助けが要った ／ できなかった |
| 止まった・探した場所 | どの画面の、どこで、何を探したか |
| 押そうとして押せなかったもの | 押せると思ったもの、押しても何も起きなかったもの |
| 予想と違った動き | 何を予想し、実際は何が起きたか |
| 言葉 | 意味が分からなかった・逆に理解した言葉 |
| 気づいたこと | 上に当てはまらない感想 |

検証した人、日時、ブラウザ、画面の大きさ、通知の置き場所の案も書く。

## 6. 修正（Claude Code）

修正方針が決まってから行う。

- 直すのは、修正方針で「直す」と決まったものだけ。
- 直すたびに、DOM に依存しないテストと、スモークテスト（`npm run smoke:creator`）を更新して通す。
- 通知の置き場所が決まったら、比較用の切り替えと、採用しなかった案の実装を消す。
- 意味論に関わる問題（Asset Specification / Character Schema / 保存互換性に影響するもの）が見つかったら、独断で確定せず、保留してレポートに記録する。

## 7. 最終確認

- 修正後の画面で、操作検証の課題 1〜9 のうち、問題があったものをもう一度行う（人）。
- 全テストとスモークテスト、検証ページが通る（Claude Code）。
- 修正後のスクリーンショットを撮り直す。

## 8. 今回やらないもの

- 新しい機能：VARIANT、PORTRAIT、一括出力、ドラッグでの配置、Undo / Redo、自動保存、検索・タグ、状態のサムネイル、ポーズのプリセット、カスタム素材の導入。
- 素体の入れ替え、同じパーツの複製。
- スマートフォン向けの配置（課題 8 で幅を見るのは、どこで崩れるかを知るため。対応はしない）。
- 正式素材の制作、見た目のデザイン（色・書体・余白の作り込み）。
- UI の技術選定（フレームワークの導入）。検証で実装上の限界が見えた場合は、レポートに記録する。

## 10. 完了条件

1. 課題 1〜9 の観察が記録されている。
2. 通知の置き場所が決まり、**通知が出ても消えても、プレビューの大きさが変わらない**。
3. 修正方針で「直す」としたものが直っている。直さなかったものは理由が記録されている。
4. 比較用の切り替えが残っていない。
5. 全テストとスモークテストが通る。検証ページが従来どおり動く。
6. Asset Specification・Character Schema・`src/core/` の意味論が変わっていない。
7. Phase 1-C-3 の検証レポートがあり、Phase 2 へ進めるかを判断できる。

Phase 1-C-3 が完了したら、Phase 1-C 全体を閉じて `phase1c-creator-ui` を main へマージする。
